Project 3: Student Academic Records and Performance Analytics System in C

1. Overview

This program manages academic records for any number of students. Users can register, view, update and delete students, add courses and update marks, search and sort records, and generate performance reports. All records are stored in dynamic memory while the program runs and saved to a text file (data/students.txt), so they are available again the next time the program starts.

The code is split into modules, each with a header in include/ and a source file in src/: records (structures and memory), search, sort, report, storage (files), validation, input, display and menu.

2. Structure Definitions and Relationships

Course: course code, course name, marks obtained and maximum marks.
Student: student ID, first name, last name, programme, year of study, number of courses (course_count) and a pointer to a dynamic array of Course records (courses).
StudentList: a pointer to a dynamic array of Student records (students) and the number of students (count).

The relationship is one-to-many twice: one StudentList owns many Students, and each Student owns many Courses. A Status enum (OK, NO_MEMORY, DUPLICATE, NOT_FOUND, INVALID, FILE_ERROR) is returned by every operation so the caller can report the exact problem.

3. Pointer Usage

Functions receive StudentList * and Student * so they change the original records rather than copies, for example student_add_course(Student *student, ...) and list_remove(StudentList *list, int id). list_get() returns a pointer to the student inside the array, which the menu uses to edit that record directly. The search functions return their results through an int ** parameter, and the sort and search modules use function pointers to pick the comparison or matching rule at runtime.

4. Dynamic Memory Allocation and Deallocation

The first student is allocated with malloc(). Each new student grows the array by one with realloc(). Deleting a student frees that student's course array, shifts the remaining students left and shrinks the array with realloc(). Course arrays work the same way per student. Every allocation result is checked; on failure the function returns STATUS_NO_MEMORY and the existing data is left untouched. list_free() releases every course array and then the student array when the program exits. Valgrind on Ubuntu reported "All heap blocks were freed -- no leaks are possible" and 0 errors.

5. Searching and Sorting Algorithms

Searching is a manual linear search. Search by ID returns the index of the matching student. Search by name checks whether the text appears in the first name, last name or full name, ignoring case. Search by programme works the same way on the programme field. Name and programme searches collect every match into a newly allocated array of indexes.

Sorting is a manual insertion sort (qsort() is not used). The user chooses the key (ID, name, overall average or programme) and the order (ascending or descending), and the matching comparison function is selected through a function pointer. Insertion sort is stable, so equal records keep their previous order. Students with no courses sort below everyone when sorting by average.

6. File Handling Implementation

Records are saved as a text file with one record per line and fields separated by '|':
S|id|first name|last name|programme|year|number of courses
C|course code|course name|marks|max marks
Each S line is followed by its course lines. Saving writes to a temporary file first and then renames it, so a failed save never destroys the previous file. Loading reads into a new list and only replaces the current data when the whole file is valid. A missing file starts an empty list, and a corrupt line (bad number, wrong field count, duplicate ID, or wrong number of courses) is reported with its line number.

7. Academic Performance Calculations

A course percentage is marks divided by maximum marks times 100, and a course is passed when it is at least 50%. A student's overall average is the total marks obtained across all courses divided by the total maximum marks, times 100. A student passes when that average is at least 50%. The report shows the total students, total course registrations, overall average, the students with the highest and lowest averages, the number passing and failing, the average and pass count per course, and the number of students per programme. Students with no courses are counted separately and never divided by zero. The report can also be saved to a file (see samples/academic_report.txt).

8. Error Handling and Testing

Input is read line by line and re-asked until valid: IDs from 1 to 99999999, year from 1 to 6, marks from 0 to the course maximum, maximum marks from 1 to 1000, and text fields that are non-empty plain ASCII without '|'. Duplicate student IDs and duplicate course codes are rejected, updating or deleting a missing student gives a clear error, invalid menu choices are rejected, and deleting asks for confirmation. On exit the program offers to save unsaved changes.

Testing uses six unit test programs (validation, records, search, sort, report, storage) with 122 checks, and an integration test that drives the real program through the menu, saves, restarts and checks the file. All tests pass on macOS and on Ubuntu with gcc.
