Project 2: Linux System Health and Resource Monitoring Manager

1. Overview

health_monitor.sh is an interactive Bash application for Linux. Its menu lets the user display system information, monitor CPU, memory and disk usage, view, search and terminate processes, generate a timestamped system health report, and view or clear the activity log. Every action, warning and error is recorded in an activity log (logs/activity.log). The script was run and tested on Ubuntu 24.04.

2. Script Structure

The script is organised into reusable functions, grouped as follows:
Helpers: log_event (writes timestamped log entries), error, require_commands (checks that utilities are installed), ask and confirm (read input safely), add_warning and flush_warnings (collect, print and log warnings).
Validation: is_valid_threshold, is_valid_pid, at_least (decimal comparison) and read_threshold.
Data collection: get_os_name, get_uptime, cpu_usage_percent, memory_stats, disk_usage.
Status printers: print_system_info, print_cpu_status, print_memory_status, print_disk_status. These are shared by the monitoring options and the health report, so no code is repeated.
Menu actions: show_system_info, monitor_cpu, monitor_memory, monitor_disk, view_processes, terminate_process, generate_report, view_log and clear_log.
Main: check_environment, show_menu and main (the menu loop). The menu only runs when the file is executed, so the test suite can load the functions with source.

3. Commands Used

hostname, uname -r / -m and /etc/os-release: host name, kernel, architecture and OS name.
uptime -p (or /proc/uptime as a fallback) and date: uptime and current date and time.
/proc/stat: overall CPU usage, measured by sampling twice, one second apart.
/proc/loadavg and nproc: load averages and the number of CPU cores.
/proc/meminfo: total, used (total minus available) and available memory, and the usage percentage.
df -hP (excluding tmpfs, devtmpfs and squashfs): disk usage per mounted filesystem.
ps -eo ... --sort=-%cpu: process lists with PID, user, CPU %, memory % and command.
kill -TERM / -KILL: terminating a process after confirmation.
awk, grep, head, tail, wc and mkdir are used for calculations and formatting, with command substitution such as $(...) and process substitution < <(...).

4. Monitoring Features

CPU: the user enters a threshold (1-100, Enter keeps the current value). The script shows cores, load average, overall CPU usage and the top 5 processes by CPU, and warns when the overall usage or any single process reaches the threshold.
Memory: shows total, used and available memory and the usage percentage, and warns when it reaches the threshold.
Disk: shows size, used, available and use % for each filesystem, and warns about every filesystem at or above the threshold.
Each warning is printed on screen and written to the log with the level WARNING.

5. Process Management

Option 5 lists running processes (the total count and the top 20 by CPU) and searches by name (case-insensitive) or by PID, showing PID, parent PID, user, CPU %, memory %, running time and command. Option 6 terminates a process: it checks that the PID is valid and exists, shows the process, refuses protected processes, asks for confirmation, sends SIGTERM, and offers SIGKILL if the process is still running. Protected processes are PID 1 and 2, this script and the shell that started it, kernel threads, system services (systemd, sshd, dbus-daemon and others), and, for normal users, processes that belong to another user.

6. Health Reports and Activity Log

Option 7 asks for a directory (Enter uses reports/), creates it if needed and saves health_report_YYYYMMDD_HHMMSS.txt. The report contains the generation time and user, system information with uptime, CPU, memory and disk status, and a list of warnings. Option 8 shows the last 50 log entries, and option 9 clears the log after confirmation. Each log line has the form [YYYY-MM-DD HH:MM:SS] [LEVEL] message (see samples/sample_activity.log and samples/sample_health_report.txt).

7. Input Validation and Error Handling

Menu choices must be 1 to 10. Thresholds must be whole numbers from 1 to 100, and PIDs must be positive whole numbers. Invalid values print a clear error, are logged, and are asked again where that makes sense.
Missing utilities: require_commands names any missing command (for example ps) and the related feature is disabled instead of crashing. The script refuses to run on non-Linux systems.
Invalid or unavailable processes: "no running process has PID N".
Insufficient permissions: other users' processes are refused, failed kill signals are reported, and a report directory that cannot be created or written is rejected, as is a path that is a file rather than a directory.
Confirmation is required before terminating a process or clearing the log. End of input (Ctrl+D) exits cleanly and is logged.

8. Testing

tests/run_in_docker.sh runs everything in a fresh Ubuntu 24.04 container. ShellCheck reported no issues. The test suite has 23 unit tests on the functions and 36 menu-driven integration tests, covering every menu option, invalid input, terminating a real process, protected processes, report generation, and viewing and clearing the log (59 passed, 0 failed). Two more checks run as a normal user: a root-owned process is refused, and an inaccessible report directory (/root/reports) is rejected.
