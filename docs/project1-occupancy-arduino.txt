Project 1: Smart Occupancy Monitoring and Access Control System

1. Overview

This Arduino Uno system, simulated in Tinkercad, monitors how many people are inside a facility with a maximum capacity of 5. The entry button adds one person and the exit button removes one. A 16x2 LCD shows the number of people inside and the remaining capacity. The green LED is on while there is space, and the red LED is on when the facility is full. The Serial Monitor reports every event, regular statistics and error messages.

2. Hardware and Wiring

Components: Arduino Uno, 2 push buttons, a green LED, a red LED, a 16x2 LCD, three 220 ohm resistors (two for the LEDs, one for the LCD backlight), a breadboard and jumper wires.
LCD: RS to pin 12, E to pin 11, D4 to D7 to pins 5, 4, 3 and 2, with RW and V0 to GND, VDD to 5V and the backlight through a 220 ohm resistor.
Buttons: entry on pin 7 and exit on pin 8, each connected to GND. The pins use INPUT_PULLUP, so a pressed button reads LOW and no external resistor is needed.
LEDs: green on pin 9 and red on pin 10, each through a 220 ohm resistor to limit the current.

3. System Operation

Entry: each valid press adds one person. When the facility is full, the entry is rejected and the Serial Monitor shows "ERROR: Entry rejected, facility is at maximum capacity".
Exit: each valid press removes one person. When nobody is inside, the exit is rejected with "ERROR: Exit rejected, nobody is inside".
So the count can never go above the capacity or below zero.
LEDs: 0 people inside means green ON and red OFF; people inside but below capacity means green ON and red OFF; capacity reached means green OFF and red ON; an entry attempted when full keeps green OFF and red ON.
LCD: line 1 shows "Inside: 3/5", and line 2 shows "Available: 2", or "FULL - NO ENTRY" when full.

4. Programming Concepts

Language: the program logic is written in C: typedef structs, an enum, pointers, calloc() and free(), stdbool.h and C-style function prototypes. Only the LCD and Serial Monitor calls (lcd.print, Serial.println) come from the Arduino libraries, which Tinkercad provides. The logic was also compiled as strict C11 with no warnings.

Structures: OccupancyRecord (a typedef struct) stores the current count, capacity, peak occupancy, total entries and exits, and rejected entries and exits. Button stores a pin and its debounce state.
Pointers: every function that reads or changes occupancy receives an OccupancyRecord pointer, for example recordEntry(OccupancyRecord *record). buttonPressed() updates a Button through a pointer, and destroyOccupancyRecord() takes a pointer to the pointer so it can set it to NULL after freeing.
Dynamic memory: createOccupancyRecord() allocates the record with calloc(), which also sets all counters to zero. The result is checked, and if allocation fails the system shows "MEMORY ERROR" on the LCD, turns the red LED on and stops processing.
Memory management: the 'r' Serial command resets the system by releasing the old record with free() and allocating a new one with calloc().
Functions: the code is split into small functions: record logic (recordEntry, recordExit, isFull, remainingCapacity), input (buttonPressed), outputs (updateLeds, updateLcd), reporting (reportEvent, reportError, reportStatistics), event handlers (handleEntry, handleExit) and setup()/loop().
Non-blocking programming: delay() is never used. Buttons are debounced with millis(): a new reading must stay the same for 50 ms before it counts, and each press counts once however long the button is held. The LCD refreshes every 250 ms and statistics print every 15 seconds, both timed with millis(), so the buttons always respond.

5. Serial Communication

Events are printed with a timestamp, for example:
[    5120 ms] ENTRY | Inside: 3/5 | Available: 2
[    9870 ms] ERROR: Entry rejected, facility is at maximum capacity | Inside: 5/5 | Available: 0
Every 15 seconds, or when 's' is typed, a statistics block shows the uptime, people inside, capacity, available places, peak occupancy, total entries and exits, rejected entries and exits, and the status (OPEN or FULL).

6. Testing

The sketch was tested in Tinkercad by pressing entry until full, trying one more entry, pressing exit until empty and trying one more exit, and checking the LEDs, LCD and Serial Monitor at each step. The same code was also run on a computer against a small mock of the Arduino functions (millis, digitalRead and digitalWrite, Serial and LiquidCrystal) with simulated time. The 46 automated checks cover startup, rejected entries and exits, the LED and LCD states, switch bounce (a flickering press counts once and a 20 ms glitch is ignored), periodic statistics, the 's' and 'r' commands, and the record functions used through pointers. All checks pass.
